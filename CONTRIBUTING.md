# Contributing to SOPGuard-Eval

Contribute research-methodology improvements by issue and pull request against a topic branch. Cite primary evidence for clinical statements and mark unverified propositions as open questions. Prefer narrow changes: evidence ledger, protocol, governance, benchmark schema and reproducibility planning.

No secrets, patient records, accession IDs, timestamps, identifiable medical notes, private SOPs or licensed IFU documents in GitHub issues, pull requests, logs or commits. Treat this public repository as fully public even when deleted later.

A PR touching clinical pathways must state the exact analyser/model/software/SOP version **and** explicitly say whether an accredited laboratory owner has validated it. No author can self-certify clinical validity or clinical deployment readiness.

No simulated patient outcomes presented as empirical clinical findings. Mark synthetic examples as synthetic. Protect frozen test cases from development. Changes to endpoints or rubric after preregistration require documented amendments and impact assessments.

Do not merge changes that claim ethics approval, lab permission, a validation result or clinical readiness unless accompanying verifiable documentation has been reviewed (private evidence may be cited by controlled reference, not uploaded).
